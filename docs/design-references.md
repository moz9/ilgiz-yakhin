## Liquid Glass

### Website Glass

- [Демо и компоненты](https://websiteglass.com/)
- SVG displacement преломляет живой DOM, сохраняя текст выделяемым. Подходит для плавающей навигации, активного переключателя и одной интерактивной линзы на главной.

### liquidGL

- [Демо](https://liquidgl.naughtyduk.com/)
- [Исходники](https://github.com/naughtyduk/liquidGL)
- Даёт полноценное преломление, блики, bevel, tilt и chromatic aberration. Использовать только как экспериментальный вариант для одной большой линзы; не делать на нём весь интерфейс.

### Blackbook / Talk to My Agent

- [Сайт](https://blackbook.dk/en/)
- [Описание проекта](https://www.designnominees.com/sites/blackbookdk)
- Взять: стеклянные переходы, слои контента за линзой и ощущение живого интерфейса.
- Не брать: разговорного AI-агента как основную навигацию и полноэкранный портрет.

### Принцип использования

Apple рекомендует Liquid Glass как отдельный функциональный слой для навигации и контролов поверх содержимого, а не как материал каждой карточки. Для портфолио это означает: стеклянный dock, переключатели, preview-линза и переходы; сами кейсы остаются чёткими и читаемыми.

## Новое рекомендуемое направление

Рабочее название: **Liquid Editorial Showreel**.

1. Первый экран похож на интерактивную обложку: имя, специальность и 3–4 небольших медиа-фрагмента лучших кейсов образуют асимметричную композицию.
2. Поверх композиции движется Liquid Glass линза. Она слегка увеличивает и преломляет элементы под собой; на touch перемещается по заданной траектории.
3. Навигация находится в компактном стеклянном dock и меняет форму активного индикатора между пунктами.
4. Входная анимация использует маски: имя и медиа собираются за 1–1,5 секунды без заставки и ожидания.
5. Четыре главных кейса проходят через одну pinned-секцию. Текст, схемы и несколько фрагментов интерфейса меняются по мере прокрутки; постоянного огромного скриншота нет.
6. После showreel расположен быстрый табличный архив всех проектов для HR.
7. Страница кейса открывается через shared transition активного медиа-фрагмента и затем возвращается к обычной читаемой структуре.
8. Раздел «Обо мне / Резюме» остаётся спокойнее и использует структуру Magic Portfolio.
9. На мобильном линза становится небольшим управляемым акцентом, pinned-секция превращается в scroll-snap последовательность, а dock остаётся доступным большим пальцем.

### Реалистичная сложность

- Motion: маски, shared transitions, dock, hover/focus и mobile sequence.
- GSAP ScrollTrigger: только pinned showreel из четырёх кейсов.
- SVG displacement: Liquid Glass для линзы и dock.
- CSS fallback: обычный полупрозрачный material при reduced motion, слабом GPU или отсутствии нужных фильтров.
- WebGL не требуется для основной версии; liquidGL можно сравнить отдельным прототипом.

## Что сознательно исключено

- Полноценная 3D-сцена, WebGL и canvas-эффекты.
- Огромные скриншоты на первом экране.
- Бесконечные карусели, курсорные шлейфы и звук.
- Стеклянные карточки вокруг каждого блока содержимого.
- Bento-сетка, шкалы навыков, вымышленные метрики и отзывы.
- Слоганы и маркетинговые утверждения, которые нельзя подтвердить.

## Система презентации кейсов

Обычный скриншот главной страницы не используется как готовая обложка. Для каждого проекта создаётся собственный набор материалов из пяти типов.

1. **Hero render** — интерфейс в уместном контексте: ноутбук, Windows-монитор, телефон, планшет или браузерное окно. Это эмоциональный кадр, а не единственное доказательство работы.
2. **Exploded UI** — композиция из 2–4 функциональных фрагментов: основной экран, важный диалог, мобильное состояние, результат операции.
3. **Readable close-up** — фронтальный фрагмент интерфейса без перспективы, достаточно крупный для чтения подписей.
4. **Flow / architecture** — короткая схема реального сценария или технического контура.
5. **Motion proof** — 6–12-секундный зацикленный ролик ключевого действия вместо длинного общего screen recording.

Device mockup не должен скрывать интерфейс. Наклон и перспектива используются только в первом атмосферном кадре; ниже экран всегда показывается фронтально. Все mockup имеют согласованный свет, фон и толщину рамок, но устройства подбираются по реальному продукту.

### Материалы по проектам

#### ChessRise

- Светлый ноутбук с реальной главной страницей, но экран занимает только часть композиции.
- Рядом отдельными слоями: интерактивная шахматная задача, мобильная заявка и подтверждение отправки.
- Короткий ролик: решение задачи → заявка → результат.
- Схема заявки: browser → server validation → PostgreSQL/RLS → Telegram/PDF.

#### Сайт ТРЦ «Пионер»

- Настольный монитор или ноутбук плюс телефон; не изображать несуществующий kiosk-продукт.
- Главным визуальным объектом сделать карту этажей, каталог арендаторов и афишу, а не hero главной страницы.
- Короткий ролик реального посетительского пути: поиск магазина → карточка → карта этажа.

#### Система подготовки отчётности рабочего времени

- Windows-ноутбук или офисный монитор, не MacBook.
- Три слоя: импорт, проверка/исключения и итоговый Excel.
- Схема source file → validation → calculation → export с отметкой неизменности исходника.
- Крупный читаемый фрагмент строки отчёта и отдельное состояние ошибки.

#### Система учёта ИТ-инфраструктуры

- Windows desktop context и несколько перекрывающихся окон приложения.
- Визуальный акцент на сверке данных, ролях и карточке оборудования, а не на dashboard целиком.
- Схема typed IPC → application services → encrypted SQLite.

#### LunaFantasy

- Не использовать главную страницу как основной кадр.
- Собрать композицию из каталога, поиска, карточки, административного workflow и production-проверки.
- Motion proof показывает пользовательский путь, а не декоративную прокрутку страницы.

#### RevaLib

- Основные визуалы: поиск/каталог, очередь модерации, audit trail и состояние конфликта версии.
- Схема ingestion → moderation → PostgreSQL → publication плюс отдельный restore drill.

## Выводы из отзывов

- Image dump без задачи, решений и результата заставляет воспринимать автора как исполнителя, а не как человека, решающего проблемы.
- Один прототип или один красивый mockup не заменяет case study; короткий записанный walkthrough помогает лучше.
- Реальный коммерческий проект следует ставить выше учебного или демонстрационного.
- На первом экране кейса должны быть понятны проблема и результат; детали можно раскрывать ниже.
- Слишком наклонённые 3D-mockup делают UI нечитаемым. Mockup должен обрамлять продукт, а не конкурировать с ним.
- Ноутбук не нужен, когда аппаратный контекст ничего не объясняет: иногда аккуратная browser frame лучше.
- Mobile-проверка обязательна: рекрутер может впервые открыть портфолио на телефоне.
- Несогласованные отступы, рамки устройств и стили визуалов быстро разрушают ощущение дорогой работы.
