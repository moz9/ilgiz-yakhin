# Редизайн портфолио: спецификация для реализации

Статус: **направление утверждено владельцем** (2026-09-26). Этот документ — задание на перенос прототипа в Next.js. Он заменяет текущий визуал сайта; `docs/design-references.md` остаётся фоновым исследованием.

Главная претензия к текущему сайту: «выглядит как проект девятиклассника, а не портфолио профессионала» — скучно, шаблонно, нет движения, не нравятся цвета, шрифты и подача проектов. Новая версия должна ощущаться живой и смелой, при этом оставаться читаемой для HR.

## Решения владельца: не нарушать

Эти решения владелец принял раньше. Прототип их учитывает; при реализации не возвращать.

- **Никаких элементов, которые следуют за курсором.** Линза в hero двигается сама по заданной траектории, стена не наклоняется за мышью. Кастомного курсора и шлейфов тоже нет.
- **Не указывать город и часовой пояс в hero.** «Барнаул · UTC+7» убран из верхней строки. Город допустим только в резюме и на «Обо мне».
- **Откровенные иллюстрации не показывать в первых рядах.** Обложки LunaFantasy (и RevaLib, где тоже аниме-арт) не используются в стене hero, не идут первыми в списке проектов и не стоят «следующим кейсом» после ChessRise. Для LunaFantasy нужна нейтральная обложка — каталог или интерфейс без персонажей крупным планом.
- **Порядок проектов** везде один: ChessRise → ТРЦ «Пионер» → Отчётность рабочего времени → Учёт ИТ-инфраструктуры → LunaFantasy → RevaLib. Это порядок `homeOrder` из текущего кода.
- **Технические утверждения проверяются по работающей версии**, прежде чем попасть в новый макет (см. этап 1 в `CODEX-TASKS.md`).

## Дизайн-система

Тема одна — тёмная, это осознанное решение. `ThemeToggle` и светлая палитра удаляются.

### Цвета

| Токен | Значение | Роль |
| --- | --- | --- |
| `--ink` | `#0d1015` | фон страницы |
| `--panel` | `#141920` | карточки, поле почты |
| `--line` | `#252c36` | линии и рамки |
| `--text` | `#eef1f4` | основной текст |
| `--muted` | `#8c96a3` | вторичный текст |
| `--amber` | `#ffb23f` | единственный акцент: вторая строка имени, прогресс, pipeline, маркеры результатов, CTA hover |
| `--ok` | `#5bd68a` | семантика: «production», «принят и оплачен», «открыт к работе» |
| `--warn` | `#ffcf5c` | семантика: «preview / в разработке» |

Старые `--teal` (который на самом деле коралловый) и `--red` (лаймовый) не переносить.

### Шрифты

Подключать через `next/font/google` с `subsets: ["latin", "cyrillic"]`:

- **Unbounded** 500/700/800 — только дисплей: имя, заголовки секций (uppercase, `letter-spacing: -0.04em…-0.05em`, `line-height: .88–.95`), названия проектов, цифры фактов.
- **Geologica** 300/400/500/600 — весь текст. Лид — 300.
- **JetBrains Mono** 400/500 — служебные подписи: uppercase, 12px, `letter-spacing: .08em`; стек и даты.

**Не использовать** контурный текст (`-webkit-text-stroke`) с Unbounded: у шрифта пересекающиеся контуры, и в буквах видны артефакты. Поэтому вторая строка имени залита янтарём, а «проект?» — тёмным `#343c48`, который на hover становится янтарным.

### Сетка и формы

- Боковой отступ: `--gut: clamp(16px, 5vw, 80px)`.
- Радиусы: карточки проектов 22px, кнопки и dock полностью скруглённые (999px), поле почты 14px, скриншоты в стене 10px.
- Карточками оформлены только проекты. Факты, опыт и pipeline разделяются линиями, без плашек.

## Главная страница: секции и поведение

Порядок: Hero → Факты → Проекты (закреплённая лента) → «До production и дальше» → Опыт → Контакт, плюс плавающий dock.

### 1. Hero

- Высота `min(900px, 100svh)`, контент прижат к низу.
- **Стена скриншотов**: 3 колонки только из обложек ChessRise, «Пионера», отчётности и учёта инфраструктуры (без LunaFantasy и RevaLib), соотношение 16:10. Каждая колонка — набор из трёх картинок, повторённый дважды для бесшовной петли. Колонки бесконечно едут вверх (`translateY(0 → -50%)`) за 46s, 60s (в обратную сторону) и 52s. Вся стена повёрнута в 3D: `rotateX(24deg) rotateY(-16deg) rotateZ(8deg)` при `perspective: 1600px`. За курсором не наклоняется.
- **Два слоя стены**: нижний — `grayscale(1) brightness(.32)`, верхний — цветной, с маской `radial-gradient(circle 190px at var(--mx) var(--my), #000 55%, transparent)`. Маску нужно вешать на обёртку без трансформации, иначе координаты линзы не совпадут со стеной.
- **Линза**: стеклянное кольцо 380px (на мобильном 240px) с внутренним бликом и слабым янтарным свечением. Двигается **сама**, по медленной фигуре Лиссажу (`x = .64 + .2·sin(.32t)`, `y = .44 + .18·sin(.51t + 1)`), и **не реагирует на курсор**. При `prefers-reduced-motion` стоит на месте.
- Затемнение: градиент слева направо и снизу, чтобы текст читался.
- Верхняя строка (mono): «● Открыт к удалённой работе» с пульсирующей зелёной точкой · «Full-stack / AI-разработчик». Города и часового пояса нет.
- **Имя**: две строки Unbounded 800, `clamp(54px, 11.5vw, 188px)`, «ИЛЬГИЗ» — `--text`, «ЯХИН» — `--amber`. Каждая буква выезжает снизу из маски (`overflow: hidden`), 0.9s, задержка 45ms на букву. У `h1` — `aria-label="Ильгиз Яхин"`, у спанов с буквами — `aria-hidden`.
- Лид (не шире 40ch): «Проектирую, пишу и выпускаю web‑продукты, desktop‑приложения и автоматизацию. **Отвечаю за систему целиком**: от интерфейса до отката релиза.»
- CTA: «Смотреть проекты ↓» (светлая, на hover янтарная) и «Резюме, PDF» — на сайте это настоящая ссылка на `/resume/ilgiz-yakhin-compact.pdf` с `download`.

### 2. Факты

Четыре колонки, разделённые линиями (на мобильном 2×2): **3** — проекта работают в production · **488** — страниц в production-сборке LunaFantasy · **41** — автотест в RevaLib, плюс restore drill · **6** — кейсов: web, desktop, автоматизация. Числа отсчитываются от нуля при появлении, но только если на момент загрузки они были ниже экрана: в неподвижном состоянии всегда видны итоговые значения.

### 3. Проекты — закреплённая горизонтальная лента

- Заголовок «ПРОЕКТЫ» и подпись справа.
- Desktop (>860px): у обёртки высота `track.scrollWidth - innerWidth + innerHeight`, внутри sticky-блок на 100svh. При вертикальной прокрутке лента сдвигается по X пропорционально прогрессу. Сверху идёт строка «04 ——— 06» с янтарной полосой прогресса. Снизу у sticky-блока `padding-bottom: 90px`, чтобы dock не перекрывал карточку.
- Карточка: `min(84vw, 1240px)` × `min(68svh, 640px)`, сетка 1.55fr / 1fr. Слева скриншот (`object-position: top left`); масштаб зависит от расстояния до центра экрана (1 → 1.18), на hover 1.02. Справа:
  - статус-пилюля с цветной точкой (mono);
  - название (Unbounded 700);
  - `task` из `projects.ts`;
  - первые три результата с янтарными маркерами, разделённые линиями;
  - стек (mono, muted).
- Порядок и статусы:

| slug | Статус на карточке | Тон |
| --- | --- | --- |
| chessrise | Принят и оплачен | ok |
| pioner | Preview · в разработке | warn |
| worktime-reporting | Windows · демо | muted |
| infrastructure-inventory | Windows · демо | muted |
| lunafantasy | Production | ok |
| revalib | Production | ok |

- Вся карточка — ссылка на `/projects/[slug]`.
- Мобильный (≤860px): без закрепления, карточки стопкой, скриншот сверху (16:10), полосы прогресса нет.

### 4. «До production и дальше»

Заголовок и абзац: «Опыт ИТ‑эксплуатации научил не отделять код от запуска. В каждом проекте я прохожу весь путь сам и оставляю заказчику систему, которую можно сопровождать.»

Шесть узлов в ряд, над ними линия:

1. Интерфейс — Next.js · React · Electron
2. API и проверки — Zod · Pydantic · FastAPI
3. Данные — PostgreSQL · RLS · SQLite
4. Тесты — Vitest · Playwright
5. Релиз — Docker · Nginx · GitHub Actions
6. Эксплуатация — backup · restore drill · rollback

Янтарная линия со свечением заполняется по мере прокрутки через секцию, и узлы по очереди загораются. На мобильном линия вертикальная, слева.

### 5. Опыт

Заголовок слева; справа строки: период (mono), должность, описание — данные с `/experience`, плюс образование (КГЭУ, 2026).

### 6. Контакт

«ОБСУДИМ / ПРОЕКТ?», Unbounded 800, `clamp(48px, 10vw, 170px)`, вторая строка `#343c48`, при наведении на секцию становится янтарной. Под ним почта `im@angelius.ru` в mono-плашке (на сайте это ещё и ссылка `mailto:`) и кнопка «Скопировать почту» с состоянием «Скопировано».

### Dock

Фиксирован внизу по центру: «Главная · Проекты · Подход · Контакт». Стекло: `rgba(22,27,35,.55)`, `backdrop-filter: blur(18px) saturate(1.8)`, рамка `rgba(255,255,255,.12)`, внутренний блик. Светлая «пилюля» переезжает к активному разделу с упругим easing `cubic-bezier(.3,1.3,.5,1)`. На внутренних страницах пункты ведут на страницы (Проекты → `/projects`, Контакт → `/#contact` и т. д.). Учитывать `env(safe-area-inset-bottom)`. **При прокрутке вниз dock уезжает за нижний край, при прокрутке вверх возвращается**; у самого верха и в конце страницы виден всегда. Так он не перекрывает скриншоты и текст при чтении, особенно на телефоне. Текущая верхняя шапка `SiteHeader` заменяется dock'ом; вордмарк можно оставить маленьким слева сверху.

## Страница кейса

Владельцу не нравится текущая подача кейсов. Эталон новой — `docs/redesign/case-prototype.html`.

### Что не так сейчас

1. **На странице кейса нет ни одного изображения.** Обложка есть в данных, но не показывается. Продукт не виден.
2. **Кейс читается как анкета.** У всех шести одинаковый шаблон «Контекст → Решения → Результат → Границы» с нумерацией 01–04, TOC слева, «CASE 04 / 06» (при этом на главной этот же проект идёт первым).
3. **Нет истории и итога.** Первым видно `summary`, а не результат. Нет короткого ответа «что было нужно, что я сделал, что получилось».
4. **Английский канцелярит**: «Accepted by client», «Commercial web launch», «Accepted and paid production project», «Versioned deployment».
5. **Оборонительный тон.** Рамка с замком «Что не заявляется / Честные границы» выглядит как оправдание и занимает больше места, чем решения.
6. **Повторы.** Плитки `evidence` дублируют список `results` («Accepted by client» и «Проект принят и оплачен заказчиком»).
7. **Нет главного сценария.** Не показано, как продукт работает для пользователя или бизнеса.

### Новая структура

1. **Шапка**: «← Все проекты» и «Кейс N из 6» — порядок как на главной.
2. **Hero**:
   - статус-пилюля;
   - название огромным Unbounded (вторая половина — янтарём), побуквенный въезд, `white-space: nowrap`, `font-size: min(11.5vw, 200px)`;
   - **строка итога** (`outcome`), 300, до 30ch, ключевая часть выделена жирным;
   - строка мета: Тип · Роль · Основа · Сайт ↗.
3. **Продукт крупно**: скриншот в рамке браузера (точки и адрес) во всю ширину, радиус 22px, янтарное свечение за ним. При появлении рамка растёт с 0.9 до 1 (CSS `animation-timeline: view()` внутри `@supports`, без него стоит на месте).
4. **Коротко** — три колонки: Задача · Что я сделал · Результат, по одному абзацу. Это TL;DR для HR.
5. **Главный сценарий** — схема из 4–6 шагов с иконками. По пунктирной линии бежит янтарная точка, шаг подсвечивается, когда точка до него доходит (цикл 5s, шаг каждую секунду). На мобильном схема вертикальная. Это сигнатурный элемент кейса.
6. **Крупно** — 2 фронтальных фрагмента интерфейса с подписями, при прокрутке медленно приближаются. Пока реальных скриншотов нет, это кадрирование обложки через `background-size` и `background-position`.
7. **Решения** — 3 строки: заголовок, который звучит как решение проблемы («Заявка, которая не теряется»), и пояснение. Без номеров.
8. **Что проверено** — `evidence` по-русски крупным Unbounded, результаты списком с зелёными галочками (без повтора `evidence`), стек в mono.
9. **Границы кейса** — тихая сноска мелким muted-текстом под пунктирной линией, без рамки и замка.
10. **Следующий кейс** — большая карточка: название, скриншот следующего проекта под наклоном 3°, на hover выпрямляется. Следующий — по общему порядку проектов (после ChessRise идёт «Пионер»).

Dock такой же, как на главной (с тем же скрытием при прокрутке вниз), активен пункт «Проекты».

Кадрирование обложки в блоке «Крупно» — только временная заглушка. В финальной версии там реальные отдельные кадры из этапа 1 `CODEX-TASKS.md`, у ChessRise — без cookie-плашки.

### Расширение данных (`src/lib/projects.ts`)

Добавить в `Project` (тексты только по-русски):

```ts
statusLabel: string;                           // «Принят и оплачен»
statusTone: "ok" | "warn" | "muted";
outcome: { lead: string; strong: string; tail?: string }; // строка итога с выделением
meta: { type: string; role: string; base: string; link?: { label: string; href: string } };
did: string;                                   // «Что я сделал», один абзац
flow: { title: string; lead: string; steps: { title: string; text: string; icon: string }[] };
closeups: { image: string; x: number; y: number; zoom: number; caption: string; alt: string }[];
```

`evidence.label` и `evidence.value` перевести на русский. `role` и `shortTitle`, если станут не нужны, удалить.

Для desktop-кейсов рамка браузера заменяется рамкой окна Windows (заголовок окна и кнопки справа). MacBook не использовать.

### Материалы, которые нужны от владельца

Сейчас у каждого проекта один скриншот (`public/cases/*.webp`), и на обложке ChessRise видна cookie-плашка. Для полноценных кейсов нужны 2–4 чистых скриншота на проект (1440 px по ширине, без cookie-баннеров и чужих данных) и, по желанию, короткие записи экрана на 6–12 секунд. Пока их нет, использовать кадрирование обложки, как в прототипе.

## Реализация

- **Прочитать `AGENTS.md`**: Next.js 16 отличается от того, что в обучающих данных. Перед кодом смотреть `node_modules/next/dist/docs/`.
- Контент брать только из `src/lib/projects.ts`, тексты в JSX не дублировать. Для статуса можно добавить в `Project` поля `statusLabel` и `statusTone: "ok" | "warn" | "muted"`.
- Server Components по умолчанию. Клиентские компоненты — только hero-стена с линзой, закреплённая лента, pipeline, счётчики, dock и кнопка копирования.
- `motion` уже есть в зависимостях. Для ленты и pipeline удобны `useScroll` и `useTransform`. Можно перенести и ванильную логику из прототипа — она небольшая.
- Картинки: у `public/cases/*.webp` размеры 1440×900 (у worktime 1280×800). В стене использовать `next/image` с `sizes` или CSS-фоны; картинки стены декоративные (`alt=""`, `aria-hidden`). Сейчас `projects.ts` ссылается на `raw.githubusercontent.com`; можно перейти на локальные `/cases/...`.
- Производительность: rAF линзы и анимации стены ставить на паузу, когда hero вне экрана (IntersectionObserver и `animation-play-state`). Стена не должна быть LCP-элементом — им должно быть имя.
- `prefers-reduced-motion: reduce`: без въезда букв, без движения стены, линза стоит на месте, лента не закрепляется (как на мобильном), счётчики сразу показывают итог.
- Доступность: видимый focus (янтарный outline), dock — это `<nav aria-label>`, декоративные слои скрыты от скринридеров, контраст текста не ниже 4.5:1.
- Тест `src/lib/public-content.test.ts` запрещает фразы «работающие системы», «шесть систем», «не набор технологий», «один контур ответственности» — в новых текстах их не использовать.
